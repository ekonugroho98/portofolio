The problem

Family money in Indonesia is shared, but the tools are not.

A typical household runs on a mix of joint and personal bank accounts, e-wallets and cash, managed by two or more people. Budgeting apps assume one user with one wallet, and spreadsheets break the moment nobody updates them. The result: couples argue about numbers nobody actually has.

01 · Shared household

One ledger, many members

Husband, wife and optional viewers share one household. Accounts can be personal or joint, and reports can be combined, per member, or per account.

02 · Chat-first input

Record money the way people talk

“Bayar listrik 450rb” is enough. The assistant resolves the category and account by name, asks when something is ambiguous, and never invents a transaction.

03 · Answers from real data

Grounded, not guessed

Every answer about money comes from a tool call against the household's own ledger: balances, budgets, trends and monthly summaries in plain Indonesian.

How it works

Claude does the reasoning. Karaya's API does the bookkeeping.

We don't let a language model “remember” anyone's finances. Claude receives a typed set of Karaya tools and decides which to call; the numbers always come back from our API. This keeps answers auditable and makes the same tools usable by any agent.

  • 1

    Tool use over the household ledger

    The assistant is instructed to always fetch data through tools before answering, so summaries, budgets and trends are computed, not hallucinated.

  • 2

    Agent-first public API (/v1)

    REST resources described in OpenAPI 3.1, long-lived scoped API keys, idempotency keys, tolerant name resolution and actionable errors, designed for agents rather than only for our own frontend.

  • 3

    Chat where families already are

    Today: the web app and a Telegram agent connected through the /v1 API. Next: an MCP server so Claude Desktop and Claude Code users can work with their household data directly.
